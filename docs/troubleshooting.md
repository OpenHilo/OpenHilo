# Troubleshooting

| What you see                                                    | What to do                                                                                                                                                                                                                                                                  |
|-----------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `npm WARN EBADENGINE`                                           | Select Node 22 or 24, verify `node --version`, then reinstall/build. A completed install on another major does not establish support. See [setup](quickstart.md#check-your-environment).                                                                                    |
| `Cannot find module @openhilo/...` or missing `dist`            | Run `npm ci --ignore-scripts --no-audit --no-fund` and `npm run build:packages` in the repository root. A tarball consumer needs its whole selected closure.                                                                                                                      |
| `Output already exists`                                         | Choose a new output directory. Existing report/run data is deliberately not overwritten.                                                                                                                                                                                    |
| `Input must be...`, missing field or invalid Boolean            | Correct the named input. Terminal boolean fields offer numbered Yes/No choices. API output wire values remain exactly `true` or `false`; submissions contain business outputs without a decision field.                                                                     |
| `suspended` or EOF at Human input                               | No result was invented. Only `review-report` and `document-review` supply resume commands. From the repository root, use the matching guide and exact Records path; `review-report` also requires the saved provider. `local-report` retains records but has no resume CLI. |
| Exit 2                                                          | Read the final status/reason. It can mean expected Human suspension, a business result that did not save, a revision/repair limit, or execution failure. It does not always mean the process crashed.                                                                       |
| `Codex CLI is unavailable`                                      | Ensure `codex --version` works and sign in through Codex. Only `review-report` offers `--provider offline`; document review and script repair require real Codex. The local report needs no AI. No fallback model is used.                                                  |
| Codex protocol request failed / invalid thread or turn identity | Check the named app-server operation and error code, then CLI configuration and protocol compatibility. Update Codex or the adapter if needed. Preserve the run and inspect effects before starting new work; no automatic replay occurs.                                   |
| SDK key/model missing                                           | Set the selected provider's key and model in the same shell; these scripts do not automatically load `.env`. See the SDK example; never commit keys. Paid API use is separate from CLI login.                                                                               |
| SDK authentication/rate-limit failure                           | Correct credentials or availability before new work. The example does not automatically retry, switch providers or assume a failed attempt was free.                                                                                                                        |
| SDK asked an unexpected question                                | This noninteractive host cancels and reports it. Use inputs that make the task self-contained, or implement a question host when embedding.                                                                                                                                 |
| `slow`, `stalled`, or `stopping`                                | Read phase and elapsed/idle time. Stopping still waits for cleanup; do not treat it as completed or start a duplicate write.                                                                                                                                                |
| Cannot resume / snapshot or log invalid                         | Preserve records and inspect the reported issue. Do not delete a live lock or replace the snapshot with freshly generated code.                                                                                                                                             |
| `unsafe to replay` / `outcome_unknown`                          | Inspect any external effect and reconcile it before new work. There is no automatic safe retry.                                                                                                                                                                             |
| Python/Bash failure or missing runner                           | Ensure host executables are installed; rebuild/repack if an archive asset is missing. Check recorded stderr/exit code. No report success is claimed on a failed save.                                                                                                       |
| Consumer install DNS/network failure                            | Package installation needs registry access for public dependencies. Tests themselves use offline provider fixtures. Audit is disabled. Retry into a new output directory after fixing access.                                                                               |

Console `Records:` paths point to nested `runs/<intent>/<workdir-key>/<run-id>`
directories. Each has `run.json`, `.snapshot`, `execution.jsonl` and `io_records`;
review hosts also write `ai-attempts.jsonl`. These may contain task inputs and model
outputs. Treat them as your application data, not material to attach publicly
without review. A missing usage report means unknown, not zero cost.

For supported syntax, consult the [language reference](../packages/compiler/LANGUAGE.md).
Ordinary TypeScript syntax outside that documented subset is not automatically
executable as a workflow. Supply `_by_ai` role/prompt literals, `_by_human` prompt
literals, and named object-literal inputs for `_by_code` as shown in examples.
